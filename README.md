# ViewTube

Видеосервис по тестовому заданию: FastAPI, PostgreSQL, React/TypeScript,
SeaweedFS и FFmpeg. Русский интерфейс с привычной структурой YouTube.
Это работающее приложение с настоящими файлами, аккаунтами и правами доступа.

## Запуск на чистой Ubuntu

Распакуйте архив, перейдите в каталог `viewtube` и выполните **одну команду**:

```bash
bash scripts/deploy.sh --demo
```

Скрипт установит Docker из официального репозитория Ubuntu, если его ещё нет,
сгенерирует секреты, соберёт контейнеры, применит миграции и создаст демо-данные.
Нужны интернет и права sudo. Проверено на Ubuntu 24.04 ARM64; рекомендуем
4 ГБ RAM, 2 CPU и минимум 20 ГБ свободного диска. Обработка длинных видео
потребует дополнительного места. Ubuntu x86_64 использует те же multiarch-образы,
но отдельный прогон на этой архитектуре не выполнялся.

Откройте **http://localhost:8080**. Swagger: **http://localhost:8080/docs**.
Пароли создаются отдельно на каждой установке. Они находятся в
`.runtime/access.txt` (в Git и архив сдачи не попадают).

На удалённой VM адрес `localhost` относится к самой VM. Для проверки с вашего
компьютера можно открыть SSH-туннель:

```bash
ssh -L 8080:127.0.0.1:8080 user@server
```

Затем откройте тот же http://localhost:8080 у себя. Для публичного домена с HTTPS:

```bash
bash scripts/deploy.sh --url https://video.your-domain.ru --demo
```

Сначала направьте DNS домена на сервер и откройте входящие TCP 80/443. Caddy
получит и будет продлевать сертификат автоматически. Публичный домен и реальный
TLS-сертификат в рамках разработки не регистрировались. Подробности —
[эксплуатация](docs/operations.md). Без `--demo` создаётся только администратор.
Повторный запуск сохраняет секреты и данные; смену адреса нужно делать осознанно
по инструкции. Команда `docker compose down` останавливает приложение и сохраняет
данные; добавлять `-v` нельзя, если они нужны.

## Что проверить

1. Зарегистрируйтесь; канал появится автоматически.
2. Нажмите **Создать**, выберите MP4/MOV/WebM/MKV, укажите название и аудиторию.
3. После загрузки откройте **Ваши видео**. Статус сменится с обработки на публикацию.
4. Откройте видео: воспроизведение, перемотка, лайк, комментарий, подписка и плейлист.
5. В студии сделайте видео приватным и добавьте email другого зарегистрированного
   пользователя. Он увидит его в **Доступные мне**; остальные получат 404.
6. Войдите модератором: разберите демо-жалобу, скройте/восстановите видео.

Демо содержит 7 пользователей, 12 коротких воспроизводимых видео (1 приватное),
комментарии, лайки, подписки, плейлист и жалобу. Обложки и ролики генерируются
локально; чужие видео не скачиваются. Счётчики просмотров в демо — синтетические.
Демо-пароль общий только для этих тестовых аккаунтов и записан в файле доступа.

| Аккаунт | Назначение |
| --- | --- |
| viewer@demo.viewtube.example.com | Зритель, приглашён на приватное видео |
| studio@demo.viewtube.example.com | Автор «Студия формы» |
| moderator@demo.viewtube.example.com | Модерация жалоб |
| admin@demo.viewtube.example.com | Роли пользователей и журнал действий |

## Реализовано

Лента, категории и сортировка, поиск по названию, адаптивный плеер с Range,
лайки/дизлайки, комментарии, каналы и подписки, плейлисты, история и продолжение
просмотра, библиотека понравившегося, загрузка с прогрессом и отменой, студия,
приватные приглашения и отзыв, модерация, управление ролями и аудит.

Бэкенд: Argon2id, серверные сессии, CSRF/Origin, лимиты запросов, ограничения
размера и длительности, приватный S3, устойчивая очередь с повторными попытками.
Инфраструктура: миграции, healthchecks, закрытая сеть БД/S3, отдельный worker,
непривилегированные контейнеры приложения, резервное копирование и восстановление.

## Проверки

```bash
bash scripts/test.sh
# Изолированная PostgreSQL для тестов. Данные приложения не затрагиваются.
docker compose exec -T api python -m app.smoke --url http://web --allow-write
# Настоящий HTTP, SeaweedFS и worker; создаёт отдельного тестового пользователя.
```

Smoke-тест удаляет созданное видео; пользователь остаётся как запись проверки.
Результаты и ограничения проверок: [протокол приёмки](docs/acceptance.md).

## Структура и разработка

- `backend/app/api` — HTTP-маршруты; `schemas.py` — входные контракты.
- `backend/app/services` — правила доступа, представления и S3; `core` — БД/безопасность.
- `backend/app/worker.py` — фоновые задания; `models.py`, `alembic` — схема и миграции.
- `frontend/src` — React, типизированный API, страницы, общие UI-компоненты.
- `infra`, `compose.yaml`, `scripts` — развёртывание, проверки, backup/restore, сдача.
- `docs` — решения, схема данных, безопасность и эксплуатация; `ai` — происхождение ИИ.

Python 3.12+, Node 24, pnpm 11.25.0. Backend зависимости закреплены в
`requirements.txt`, frontend — в `pnpm-lock.yaml`. Для локальной разработки:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r backend/requirements-dev.txt
# Укажите DATABASE_URL, SECRET_KEY, S3_* и APP_ORIGIN согласно .env.example.
cd backend
alembic upgrade head
uvicorn app.main:app --reload
# В отдельных терминалах: python -m app.worker; cd frontend && pnpm install && pnpm dev
```

Vite проксирует `/api` на порт 8000. Для Vite задайте `APP_ORIGIN=http://localhost:5173`.
БД и S3 должны быть доступны процессам разработки; основной воспроизводимый
способ запуска — Docker. Интеграционные тесты требуют отдельную БД с суффиксом
`_test`, FFmpeg и переменную `TEST_DATABASE_URL`. `ruff check backend scripts`
проверяет Python, `pnpm build` — TypeScript и production-сборку.

## Границы решения

Обработка создаёт одну MP4-версию до 720p, без HLS/CDN и нескольких качеств.
Лимит загрузки — 512 МиБ, длительности — 2 часа. Есть прогресс отправки файла;
серверная обработка показывает состояние, а не выдуманный процент. Email не
подтверждается; восстановления пароля, биллинга, live-трансляций и рекомендаций
на ML нет. Это цельное решение тестового, а не заявка на масштаб YouTube.
Высокая доступность, антивирус, квоты хранения, нагрузочный аудит и реальный
публичный TLS требуют отдельной производственной подготовки.

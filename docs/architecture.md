# Архитектура ViewTube

Модульный монолит FastAPI обслуживает API. React/TypeScript отвечает за клиент.
PostgreSQL хранит данные и устойчивую очередь обработки; S3-совместимый SeaweedFS 4.52 —
исходники и обработанные медиа. Отдельный worker проверяет FFprobe и преобразует
видео FFmpeg в H.264/AAC MP4 с faststart. Caddy раздаёт frontend и проксирует API;
для домена автоматически получает TLS-сертификат.

Очередь в PostgreSQL использует SELECT FOR UPDATE SKIP LOCKED и ограниченные
повторные попытки. Это устраняет отдельный брокер для небольшого приложения и
сохраняет постановку задания в одной транзакции с состоянием видео. Производственная
эволюция: выделенный брокер, квоты, HLS/CDN и независимое масштабирование воркеров.

Выдача медиа проходит через авторизованный endpoint, включая Range и превью.
Поэтому отзыв приглашения блокирует новые запросы немедленно, без ожидания
истечения подписанного URL. Уже полученные пользователем байты отозвать нельзя.
Компромисс — нагрузка на API; для большого трафика потребуется CDN с проверкой доступа.

Пароли: Argon2id. Сессии: случайный токен в HttpOnly cookie, в БД только SHA-256.
Запросы изменения данных требуют CSRF-токен и проверку Origin. Роли проверяются
на сервере. Индексы, уникальные ограничения и внешние ключи защищают целостность.

Границы: api — HTTP-контракт; services — доступ/медиа/задачи; core — конфигурация,
БД и безопасность; models — ORM; schemas — валидация входа/выхода. Не вводим
универсальные репозитории, которые только повторяют SQLAlchemy Session.

Официальные справочники: https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/
и https://docs.sqlalchemy.org/en/20/core/selectable.html . Реализация использует
серверные сессии, не JWT из примера FastAPI.

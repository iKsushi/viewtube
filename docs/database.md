# Схема данных

PostgreSQL 17, SQLAlchemy 2, Alembic. Схема воспроизводится миграцией
`7d66caee2c55`; UUID представлены строками, время хранится с часовым поясом UTC.
Медиа находятся в S3, в БД — только ключи, MIME, размер и связи. 17 таблиц:

| Таблица | Назначение и связи |
| --- | --- |
| users | Уникальный нормализованный email, Argon2id, роль, блокировка |
| channels | Ровно один канал на пользователя, уникальный handle |
| sessions | Хеш токена, пользователь, срок действия; индекс по хешу/сроку |
| videos | Канал, метаданные, видимость, состояние, скрытие, длительность |
| video_assets | Source/playback/thumbnail; уникальны ключ и пара видео+тип |
| video_grants | Разрешение конкретному пользователю; уникальная пара |
| reactions | Одна реакция пользователя на видео; CHECK −1/1 |
| comments | Автор и видео, текст; индекс видео |
| subscriptions | Уникальная пара подписчик+канал |
| playlists | Канал, название, public/private |
| playlist_items | Видео в плейлисте, позиция; без дубликатов |
| reports | Одна жалоба пользователя на видео, решение и ответственный |
| processing_jobs | Одно задание на видео, попытки, аренда, токен исполнителя |
| view_events | Уникальная тройка видео+псевдоним зрителя+дата |
| watch_history | Последняя позиция и время, уникальная пара пользователь+видео |
| audit_events | Кто, когда, действие, цель, дополнительные поля |
| rate_buckets | Атомарный счётчик запросов по ключу и временному окну |

Foreign keys с CASCADE удаляют зависимые реакции, комментарии, grants и задания;
аудит сохраняется с nullable actor. CHECK фиксируют допустимые роли, состояния
и видимость. Индекс ленты покрывает hidden/visibility/status/created_at. ILIKE
экранирует пользовательские `%` и `_`; для большого каталога полезен pg_trgm.

Состояния видео: draft → uploading → queued → processing → ready. Ошибка →
failed → повторная загрузка. Удаление во время активной обработки запрещено.
Блокировки строк предотвращают одновременное назначение задания; lease_token
не даёт старому исполнителю опубликовать результат после перехвата задания.
Лайки, подписки, grants, просмотры опираются на уникальные ограничения и UPSERT.

S3 и PostgreSQL не имеют общей транзакции. При ошибках новые объекты удаляются
компенсирующим действием. При удалении видео сначала скрывается; ошибка удаления
из S3 оставляет запись для повторной попытки. После аварий возможно появление
неиспользуемых объектов; автоматический garbage collector не реализован.

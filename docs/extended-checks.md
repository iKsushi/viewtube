# Проверки браузеров и предельных видео

Все проверки записи выполнять на тестовой установке. Создаются отдельные пользователи;
браузерные тесты оставляют видео. Граничный тест удаляет успешно проверенные видео.

## Настоящий Google Chrome

Установить Chrome, Node и pnpm. Указать URL и абсолютный путь к короткому MP4:

```bash
E2E_BASE_URL=http://localhost:18088 E2E_MEDIA_FILE=/absolute/sample.mp4 bash scripts/chrome-check.sh
```

Используется channel chrome. Отсутствие H.264 считается ошибкой, не пропуском.

## Настоящий Safari на Mac

В Safari включить Settings → Developer → Allow remote automation.
Запустить `safaridriver -p 4444`, затем:

```bash
python3 scripts/safari_check.py --url http://localhost:18088 --media /absolute/sample.mp4
```

Это настоящий Safari через штатный WebDriver, не Playwright WebKit. Требуется
разрешение macOS/Safari на автоматизацию; отказ не является результатом теста приложения.

## Ubuntu x86_64

На новой Ubuntu x86_64 распаковать репозиторий и выполнить:

```bash
bash scripts/ubuntu-x86-check.sh
```

Скрипт проверяет архитектуру и ОС, разворачивает систему и запускает приёмку.
Запуск на ARM64 отклоняется. Успех на ARM64 или эмуляция отдельного контейнера
не заменяют эту проверку. Требуются сеть и sudo. Учитывать пропуски браузеров.

Для медленной полной эмуляции CPU доступен явный режим:

```bash
sudo env E2E_EMULATED=1 bash scripts/e2e.sh
# Или только WebKit для диагностики:
sudo env E2E_EMULATED=1 bash scripts/e2e.sh --project webkit
```

Режим даёт 10 минут на сценарий и 30 секунд на ожидания assert вместо
3 минут/5 секунд. Проверки, кодек и число повторов не меняются. Это проверка
функций, а не норматив скорости интерфейса. Результаты пишутся в
`.runtime/e2e-results/report.json`; выбранный один браузер не заменяет всю матрицу.

## Предельные видео

После сборки текущего backend в тестовом Compose:

```bash
docker compose exec -T api python -m app.limits_check --url http://web --allow-write
```

Реальные файлы: MP4 ровно 536870912 байт, видео ровно 7200 секунд и 7201 секунда.
MP4 дополняется корректным free-box, без подмены Content-Length. Проверяются
загрузка через прокси, состояние worker, длительность результата и превью.
7201 секунда должна дать failed и запрет воспроизведения. Двухчасовой ролик
синтетический, 32×32, 1 fps на входе: это проверка длительности, не нагрузочный
тест двухчасового 4K. Тест может идти до 70 минут на случай; оставляет данные
при ошибке для диагностики. Лимит размера +1 байт также покрыт backend-тестом.

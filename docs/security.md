# Безопасность и границы доверия

| Действие | Гость | Пользователь | Владелец | Модератор / admin |
| --- | --- | --- | --- | --- |
| Публичное опубликованное видео | Да | Да | Да | Да |
| Приватное видео / превью / Range | Нет | Только по grant | Да | Только по grant |
| Метаданные и приглашения | Нет | Нет | Да | Нет |
| Комментарий, реакция, подписка, жалоба | Нет | При наличии доступа | Да | При наличии доступа |
| Скрытие / восстановление по жалобе | Нет | Нет | Нет | Да |
| Изменение ролей | Нет | Нет | Нет | Только admin |

Роль сотрудника не обходит приватность. Скрытое видео не воспроизводится даже
владельцем; владелец видит состояние в студии. Сотрудник получает метаданные жалобы,
но не автоматический доступ к приватному файлу. Клиентские проверки служат UX;
авторизация всегда выполняется на API для каждого endpoint, включая медиазапросы.

Пароли хешируются Argon2id. Случайные токены сессий приходят в HttpOnly SameSite=Lax
cookie; БД хранит SHA-256. HTTPS-конфигурация включает Secure. Logout и изменение
роли отзывают сессии. Для мутаций требуется double-submit CSRF и проверка Origin.
IP для лимитов и просмотров преобразуется HMAC с серверным секретом. API скрыт
за Caddy; только ему доверены forwarded-заголовки, прямой порт API не публикуется.

Вход ограничен по IP и email, прочие мутации — по пользователю. Запросы БД
параметризованы, текст React экранирует. Медиа не имеют публичных URL S3;
доступ через API проверяется заново, ответы private/no-store. Отзыв приглашения
блокирует новые запросы; уже скачанные или буферизованные байты отозвать нельзя.

FFprobe/FFmpeg запускаются без shell, с ограничением форматов и протоколов,
времени, разрешения и размера. HLS/сетевые playlist-входы отклоняются. Worker
работает без root/capabilities в закрытой Docker-сети; контейнер приложения
имеет read-only rootfs и выделенный scratch-диск. Это уменьшает поверхность
атаки, но не заменяет регулярные обновления FFmpeg и контейнеров.

Секреты генерируются при установке, `.env` имеет 0600, `.runtime` — 0700. Не
публикуйте их и резервные копии. JSON конфигурации S3 читаем контейнером, но его
родительский каталог доступен только владельцу. Caddy задаёт CSP, nosniff,
frame-ancestors, Permissions-Policy. Swagger использует CDN отдельно от приложения.

Для публичной эксплуатации нужны подтверждение email/восстановление пароля,
квоты диска, мониторинг свободного места и заданий, политика удаления/хранения,
процедура обработки жалоб и резервная копия вне сервера. Pen-test, нагрузочная
сертификация и отказоустойчивость не заявляются. Администратор хоста технически
имеет доступ к БД/S3; прикладная приватность не является end-to-end шифрованием.

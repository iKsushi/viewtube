# Финальная приёмка и упаковка

1. На новой Ubuntu распаковать исходники и выполнить `bash scripts/deploy.sh --demo`.
   Записать commit, архитектуру CPU, версию Ubuntu и время. ARM64 и x86_64 учитывать отдельно.
2. Выполнить `bash scripts/test.sh`, затем
   `docker compose exec -T api python -m app.smoke --url http://web --allow-write`.
3. Выполнить `bash scripts/e2e.sh`: Chromium, Firefox и WebKit проходят регистрацию,
   загрузку, обработку, фактическое воспроизведение, лайк и комментарий с проверкой
   сохранения после перезагрузки. Тест оставляет отдельные аккаунты и видео;
   использовать только тестовую установку. WebKit не заменяет физический Safari.
4. Проверить вручную приватные приглашения/отзыв, модерацию и внешний вид всех экранов.
   Отдельно проверить файл около лимита 512 МиБ и длительность около 2 часов.
   Не отмечать эти проверки пройденными по результату короткого E2E.
5. Записать команды, результаты и ограничения в docs/acceptance.md. Сохранить логи
   локально. Зафиксировать исходники обычным коммитом без переписывания истории.
6. Собрать ZIP через scripts/package.py. Передать каждый исходный JSONL через
   повторяемый --session. Для дополнительных чатов явно передать
   --allow-session-id UUID. Использовать только диалоги этого проекта, без изменения байтов.
7. Проверить ZIP: .git, README, docs, tests, ai, исходные JSONL и манифест SHA-256.
   Распаковать в новый каталог, проверить git fsck и повторить запуск.
   Просмотреть содержимое перед отправкой. Отправка не входит в процедуру.

Новые браузерные тесты не считаются пройденными до реального запуска.

На развёрнутой тестовой Ubuntu автоматические этапы объединены командой
`sudo bash scripts/acceptance.sh`. Лог с commit и средой сохраняется
в `.runtime/acceptance/`; сбой любого этапа останавливает процедуру.

Проверять не только exit code, но и число skipped: сборки без H.264
помечаются SKIP, а не PASS. Для полной приёмки повторить сценарий
на сборке соответствующего браузера с поддержкой H.264.
`scripts/acceptance.sh` дополнительно проверяет JSON-отчёт через
`scripts/check_e2e_report.py`: skipped, flaky, errors или отсутствие пройденных
тестов останавливают процедуру. Отдельные успешные прогоны Chrome/Safari
фиксируются в протоколе; они не превращают SKIP Linux Chromium в PASS.

Расширенные проверки настоящих Chrome/Safari, Ubuntu x86_64 и предельных
видео: [extended-checks.md](extended-checks.md).
